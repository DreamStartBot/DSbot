# Performance 插件

Microbot 的 **Performance** 插件负责把客户端的性能与声音设置调整到一个适合长时间挂机的状态。

插件默认启用，不需要手动打开。

## 它做什么

| 功能 | 实现 | 时机 |
|---|---|---|
| 启用 FPS Control | 启用上游的 `FPS Control` 插件 | 插件启动时一次 |
| 启用 Low Detail | 启用上游的 `Low Detail` 插件 | 插件启动时一次 |
| 关闭游戏声音 | 音乐音量置零 + 拦截声音事件 | 启动即生效，之后持续 |

## FPS Control

被自动启用，但**限速开关和目标帧率不会自动打开** —— 这两项仍需在 FPS Control 自己的面板里设置。

原因是 FPS Control 有两道独立开关：插件本身，以及设置里的 `limitFps`。本插件只负责第一道。完整说明见 [fps-control.md](fps-control.md)。

## Low Detail

被自动启用。它的 `lowDetail` 配置默认就是 `true`，也就是启用插件的同时就已经在隐藏地面装饰、简化贴图了。

`hideLowerPlanes`（只渲染当前所在平面）默认关闭，需要的话自己去面板里开。

## 关闭游戏声音

分四种声音，分别用不同的方式关掉：

| 声音 | 方式 |
|---|---|
| 音乐 | `client.setMusicVolume(0)` |
| 音效（界面点击、攻击、采集等） | 拦截 `SoundEffectPlayed` 事件并 `consume()` |
| 区域音 | 拦截 `AreaSoundEffectPlayed` 事件并 `consume()` |
| 环境音（魔法树、熔炉那种） | `client.getAmbientSoundEffects().clear()` |

### 为什么不走游戏内 Settings 界面

游戏内 Settings 有三个音量滑块，把它们拖到 0 也能静音。但那需要操作界面，而界面的 widget 坐标会随游戏更新漂移，一漂移就静不了音。

改成直接用客户端接口和声音事件之后：

- 不依赖任何界面坐标，不会因为游戏更新而失效
- 客户端一起就能生效，不用等进游戏
- 是持续拦截，不是一次性设置，切号也不用重做

### 副作用

**界面反馈音效也没了** —— 点按钮、砍树、攻击都没有声音提示。

**不影响脚本判定** —— 脚本读的是客户端数据（NPC、物品、瓦片），不读声音。

**音乐音量会在登录后被覆盖一次**。登录流程会用本地设置重读音乐音量，所以插件在登录进游戏后会再设一次零。

### 禁用之后

在 Community Plugins 面板里禁用 Performance 即可：

- 音乐音量会还原成插件启动前的值
- 音效与区域音是拦截事件实现的，插件一停就自动恢复
- 环境音同理

但**不会**把 FPS Control 和 Low Detail 重新关掉。这两个插件的启用状态是持久化的，已经写进了配置。

### 排查

如果还有声音，按这个顺序查：

1. 确认 Performance 插件是启用状态
2. 确认自己不在上游 Music 插件里单独开了某些分类静音（那些是另一套机制）
3. 如果只有音乐还在响，看日志里有没有 `Performance:` 开头的警告

用 CLI 可以直接查当前音量：

```powershell
./microbot-cli varbit <id>
```

## 与其他设置的关系

本插件只调整客户端这一层，不碰游戏引擎自己的帧率设置。三者取最严格的那个：

| 机制 | 管什么 |
|---|---|
| 游戏内 Settings → Game FPS Limit | 画面流畅度、相机旋转 |
| GPU 插件的 Unlock FPS | 相机移动的 50 FPS 上限（默认已开，目标 60） |
| FPS Control（本插件启用） | CPU 占用 |
