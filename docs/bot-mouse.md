# Bot Mouse 插件

Microbot 的 **Bot Mouse** 插件负责画那个风扇准星，并且在**没有脚本在跑的时候**，也让它跟着真实鼠标移动。

插件默认启用，不需要手动打开。

## 它做什么

| 状态 | 准星位置 |
|---|---|
| 有脚本在跑，且移动过鼠标 | bot 的目标位置（原有行为，不变） |
| 没跑脚本，或脚本没移动过鼠标 | 真实鼠标在游戏画布里的位置 |

外观是**白色轮廓圆 + 里面 3 片旋转的风扇叶 + 灰色移动轨迹线**。

**未登录时不会跟随。** 客户端启动到进游戏之前，准星不显示。

## 为什么原来看不到准星

上游那个准星（`MicrobotMouseOverlay`）的位置取自 `PointerState.lastBotPoint()`。那个值只有脚本移动过鼠标之后才会被写入，所以：

- 客户端刚启动、脚本没跑 → 没有 bot 位置 → 准星不画
- 脚本跑过一次 → bot 位置被记住了，但那也已经是脚本移动鼠标时的位置

本插件用另一个 overlay 来画准星，位置来源按上面的规则切换。

## 和 DevTools 的 "Bot Mouse" 是什么关系

两者会画在同一处，所以本插件启动时会**把 DevTools 面板里的 "Bot Mouse" 按钮关掉**，禁用本插件时再把它恢复。

DevTools 那个按钮的开关方法 `DevToolsButton.setActive(boolean)` 是包私有的，所以本插件放在 `net.runelite.client.plugins.devtools` 包下才能调用它。同包的 `MicrobotMouseOverlay`、`MicrobotClickOverlay` 也是这么放的。

**两者的外观不一样。** 本插件是白色轮廓圆 + 旋转风扇叶；DevTools 那个（`MicrobotMouseOverlay`）是彩虹准星。本插件没有改动 `MicrobotMouseOverlay`，所以它保持原样。

**如果你在 DevTools 面板里手动把 "Bot Mouse" 打开，会出现两个准星。** 正常用不到那个按钮。

DevTools 是开发者插件，safe mode 下不加载。这时本插件自己画准星，不依赖它，功能照常。

## 位置是怎么判定的

真实鼠标位置来自 `PointerState.get()`。这个值在两种情况下都会被写：

- 真实鼠标移动 → `setFromReal()` 写入
- bot 移动鼠标 → `setFromBot()` 写入

所以它始终是「当前有效的光标位置」。脚本跑不跑，它都准。

判断「跟 bot 还是跟真实鼠标」的条件是**有没有 bot 位置**，而不是「脚本在不在跑」。因为有些脚本在跑的时候并不会移动鼠标 —— 比如某些脚本在等条件满足 —— 那种情况下 bot 位置并不存在。按脚本状态硬切的话，准星会莫名其妙地消失。

## 未登录时为什么不跟随

未登录时，canvas 上没有挂真实鼠标的监听（客户端只在登录后才挂），所以拿不到真实鼠标位置，准星不显示。

这是有意为之：登录之前没有跟随的价值，客户端启动到进游戏这一段保持干净即可。

另外，未登录时如果跑了某个会移动鼠标的脚本（比如自动登录），准星仍然会跟着 bot 位置走 —— 那是脚本自己在动鼠标，不是跟随真实鼠标。

## 样式

白色轮廓圆 + 里面 3 片旋转的风扇叶 + 灰色移动轨迹线。

| 元素 | 参数 |
|---|---|
| 轮廓圆 | 直径 16px，纯白，线宽 1.5，不填充 |
| 扇叶 | 3 片，`Color(255,255,255,180)`，线宽 1.2，填充 + 描边 |
| 中心点 | 2px 实心圆 |
| 转速 | 480 度/秒（每帧 8 度） |
| 轨迹线 | `Color(200,200,200,120)`，线宽 2，圆头圆角 |

转速按实际经过的时间累加，所以帧率变化时转速不会变。

准星从「有位置」变成「没位置」（比如切出游戏、脚本停掉）再变回有位置时，风扇角度不会跳变 —— 位置丢失时会把时间基准重置掉。

## 轨迹线

轨迹每个点存活 200 毫秒，到期就移除。鼠标停下来之后，轨迹会在这段时间内收缩消失，准星本身留在原地。

原版是靠 `Mouse` 类里的 `Timer(14ms)` 每 14 毫秒弹掉一个点来让轨迹收缩，寿命取决于点数。这里改成给每个点记时间戳，寿命是确定的。

另外，位置来源在「跟 bot」和「跟真实鼠标」之间切换时会清空轨迹，避免把两个位置连成一条线。

### 轨迹是独立存储的
本插件不共用 `Microbot.getMouse()` 的轨迹数据，而是自己维护一份。

原因是 `MicrobotMouseOverlay` 的 `else` 分支每帧都会执行：

```java
Microbot.getMouse().getPoints().clear();
Microbot.getMouse().getTimer().stop();
```

就算它自己不画准星（按钮被关掉时走的正是这条分支），它照样每帧清空数据。所以两边必须各存各的。

## 真实鼠标移出画布时

准星会停在最后一个位置，不会消失。

这是 `PointerState.setOutside()` 的设计：坐标被保留而不是清成 (-1,-1)，因为清掉的话会让所有读光标位置的 overlay 拿到无意义的值。

## 禁用

在 Community Plugins 面板里禁用 Bot Mouse 即可。禁用后：

- 准星消失，DevTools 面板的 "Bot Mouse" 按钮恢复开启
- 那个按钮恢复后，DevTools 的准星回到原有行为：只在脚本移动过鼠标之后才显示

可以反复启用禁用，不会报错。插件内部的定时任务（用来判断脚本有没有在跑）跟随插件生命周期创建和销毁。
